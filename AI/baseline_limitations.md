# Baseline 모델 문제점 분석

add-part.md 2번 요구사항에 따라, 1단계에서 구축한 **TF-IDF + LogisticRegression baseline**과 **키워드 fallback**의 한계를 분석한 문서입니다.

---

## 1. 분석 목적

baseline은 빠르고 단순하지만, 실제 매장 고객 메시지에는 **완곡 표현·문맥·감정/긴급도 분리**가 필요한 경우가 많습니다.  
이 문서는 baseline이 **틀리기 쉬운 메시지**를 정리하고, **sentiment와 severity가 다른 이유**를 설명하며, **구조적 한계**를 분석합니다.

---

## 2. sentiment와 severity는 왜 다른 개념인가?

| 구분 | sentiment (감정) | severity (긴급도) |
|------|------------------|-------------------|
| 질문 | 고객 기분이 어떤가? | 얼마나 빨리 대응해야 하는가? |
| 관점 | 심리·감정 톤 | 운영·업무 우선순위 |
| 값 예 | negative, neutral, positive | low, medium, high |
| 결정 요인 | 불만·실망·만족 표현 | 금전 피해·안전·대기 시간·확산 가능성 |

**같은 문장이라도 감정과 긴급도는 다를 수 있습니다.**

예를 들어 "환불 가능 여부만 확인해 주세요"는:
- **sentiment**: 격한 불만이 아니므로 `neutral`에 가깝고
- **severity**: 단순 문의이므로 `low`에 가깝습니다.

반대로 "결제가 두 번 됐는데 즉시 확인 부탁드립니다"는:
- **sentiment**: `negative` (문제 상황)
- **severity**: `high` (금전 피해, 즉시 대응 필요)

→ baseline은 두 라벨을 **별도 모델**로 학습하지만, **문맥을 깊게 이해하지 못하면** 둘 다 `negative / medium`으로 쏠리기 쉽습니다.

## 4. baseline이 틀릴 가능성이 높은 메시지 10개

아래 문장은 add-part.md 예시(`괜찮긴 한데 다시는 안 올 것 같아요.`)를 포함해, **완곡 표현·키워드 부재·클래스 편향** 때문에 오분류되기 쉬운 사례입니다.

실제 1단계 모델(`tfidf_lr`, `keyword_fallback`)로 예측한 결과를 함께 기록했습니다.

| # | 메시지 | 적정 라벨 | tfidf_lr 예측 | keyword 예측 | 오분류·문제 요약 |
|---|--------|-----------|---------------|--------------|------------------|
| 1 | 괜찮긴 한데 다시는 안 올 것 같아요. | negative / medium | negative / medium | **neutral** / medium | 키워드: "괜찮"에 속아 부정 감정 누락 |
| 2 | 기대했던 것과 달라서 실망했어요. | negative / medium | negative / medium | **neutral** / medium | 키워드: "실망" 미등록 → 부정 누락 |
| 3 | 환불 가능 여부만 확인해 주세요. | neutral / **low** | **negative** / medium | negative / **high** | 감정·긴급도 모두 과대 평가 |
| 4 | 결제가 두 번 됐는데 즉시 확인 부탁드립니다. | negative / **high** | negative / **medium** | neutral / **low** | 키워드: "중복 결제" 미매칭, 긴급도 과소 |
| 5 | 오늘 커피 맛은 괜찮았어요. | **neutral** / **low** | **negative** / medium | neutral / medium | tfidf_lr: 학습 편향으로 부정 과예측 |
| 6 | 그냥 그렇습니다. | neutral / low | **negative** / medium | neutral / medium | tfidf_lr: 모호 문장을 negative로 쏠림 |
| 7 | 품절이라서 다른 메뉴로 바꿨는데 괜찮아요. | neutral / medium | negative / medium | neutral / medium | tfidf_lr: "괜찮" 있어도 negative 예측 |
| 8 | 영수증만 재발급 부탁드립니다. | neutral / **low** | **negative** / medium | neutral / medium | tfidf_lr: 단순 요청을 negative로 분류 |
| 9 | 9분 넘게 기다렸는데 아직 안 나왔어요. | negative / medium | negative / medium | **neutral** / medium | 키워드: "지연" 없이 숫자+대기만으로는 부정 누락 |
| 10 | 사고가 날 뻔했는데 다행히 괜찮았습니다. | negative / **high** | negative / **medium** | neutral / high | tfidf_lr: 안전 이슈인데 medium으로 과소 |

### 대표 사례 상세: add-part.md 예시

> **"괜찮긴 한데 다시는 안 올 것 같아요."**

| 관점 | 분석 |
|------|------|
| 인간 판단 | 표면은 완화되어 보이지만, **재방문 거부·이탈 의사**가 드러나므로 **부정 감정**에 가깝다 |
| 키워드 모델 | "괜찮"이 앞에 있어 **neutral**로 오판하기 쉬움 |
| tfidf_lr | 이번 데이터에서는 negative로 맞췄으나, 학습 데이터에 유사 패턴이 적으면 **neutral로 틀릴 수 있음** |
| 핵심 한계 | **앞부분 긍정 + 뒷부분 부정** 구조를 단어 빈도만으로는 안정적으로 해석하기 어렵다 |

## 5. baseline 구조적 한계 분석

### 5-1. TF-IDF + LogisticRegression 한계

| 한계 | 설명 |
|------|------|
| 문맥 미이해 | 단어/문자 빈도만 보므로 "괜찮은데 ~ 안 올 것 같아요" 같은 **역접 구조**를 약하게 처리 |
| 클래스 편향 | sentiment negative 75%, severity medium 50% → **negative / medium으로 쏠리는 경향** (예: "오늘 커피 맛은 괜찮았어요" → negative) |
| 완곡·함축 표현 | "실망", "아쉽", "그냥 그렇다" 등 학습 빈도 낮은 표현에 약함 |
| severity 3클래스 | low/medium/high 경계가 모호해 테스트 정확도 **68.3%**에 머무름 |
| 신조어·변형 | "중복 결제"와 "결제가 두 번"처럼 **표현이 조금만 달라도** 패턴 인식 실패 |

### 5-2. 키워드 Fallback 한계

| 한계 | 설명 |
|------|------|
| 키워드 목록 고정 | add-part.md 7~12개 키워드만 매칭, "실망·이탈·중복" 등 **목록 밖 표현 무시** |
| 순서·문맥 무시 | "괜찮긴 한데"처럼 앞뒤 감정이 다를 때 **앞 키워드만 반영** |
| 부분 문자열 매칭 | "중복 결제"는 있어도 "결제가 두 번"은 **high로 잡지 못함** |
| sentiment 2값만 | positive 클래스 없음, neutral/negative 이분법 |
| severity 단순 우선순위 | high → medium → low 순차 매칭, **복합 상황**(불만+단순문의) 구분 어려움 |

### 5-3. 공통 한계

```
고객 message
    → [표면 단어 추출] → [빈도/키워드 매칭] → sentiment / severity
              ↑
        문맥·의도·완곡 표현은 이 단계에서 손실
```

- **감정(sentiment)** 과 **긴급도(severity)** 를 별도 모델로 학습해도, 입력 표현이 동일한 TF-IDF/키워드 방식이면 **같은 편향**을 공유한다.
- 관제센터에서는 오분류 시 **불필요한 에스컬레이션** 또는 **놓친 긴급 사건**으로 이어질 수 있다.

## 6. 한계 유형별 정리

| 유형 | 설명 | 대표 예시 |
|------|------|-----------|
| 완곡 부정 | 겉으로는 중립/긍정처럼 보임 | 괜찮긴 한데 다시는 안 올 것 같아요 |
| 키워드 부재 | 규칙·학습에 없는 표현 | 기대했던 것과 달라서 실망했어요 |
| 감정≠긴급도 혼동 | 한 라벨만 맞거나 둘 다 틀림 | 환불 가능 여부만 확인해 주세요 |
| 클래스 편향 | negative/medium으로 과다 예측 | 오늘 커피 맛은 괜찮았어요 |
| 표현 변형 | 같은 의미, 다른 wording | 결제가 두 번 됐는데… (≠ 중복 결제) |
| 모호 문장 | 맥락 없이 판단 어려움 | 그냥 그렇습니다 |
| 안전·금전 이슈 | severity 과소 평가 | 사고가 날 뻔했는데… |

## 7. baseline 문제 분석 결론

1. **sentiment와 severity는 반드시 분리**해서 설계·평가해야 한다. 같은 문장도 두 값이 다를 수 있다.
2. **키워드 fallback**은 구현이 쉽지만 완곡 표현·동의어 변형에 취약하다.
3. **TF-IDF + LR**은 학습 데이터 편향 때문에 **negative / medium 쏠림**이 관찰되며, severity 3클래스 정확도도 제한적이다.
4. add-part.md가 지적한 **"괜찮긴 한데…"** 유형은 baseline 전반의 대표적 약점(완곡 부정)을 보여 준다.
5. 이러한 한계 때문에 **4단계 Hugging Face 한국어 BERT** 탐색이 필요하다. 문맥 기반 모델이 완곡 표현·감정/긴급도 분리에 유리하다.

## 9. 요약

- baseline은 **빠른 1차 분류**에는 유효하지만, **완곡 부정·감정/긴급도 분리·표현 변형**에서 구조적 한계가 있다.
- 특히 학습 데이터 편향으로 **negative / medium 과예측**이 나타난다.
- Hugging Face BERT 계열 모델은 이러한 한계를 줄이기 위한 **다음 단계**이다.
